# Proposal

## Why

个人微信号每天涌入大量消息，真正需要本人处理的是少数。希望有一个常驻在 macOS 上的小服务：把微信消息接进 LLM，对白名单内的联系人给出**带上下文、像本人语气**的回复，其余消息静默忽略。这样既能把「秒回熟人」这件事自动化，又能把骚扰与垃圾信息挡在模型调用之前，顺带把 API 成本控制在可预期范围内。

## What Changes

- 新增一个 Python 3.11+ 常驻服务，通过腾讯官方 **iLink Bot API（ClawBot）** 接入个人微信；纯出站 HTTPS 长轮询，不依赖微信客户端、不依赖 Windows，可直接在 macOS 上运行。
- 新增二维码登录与会话续期：首次启动扫码获取 `bot_token`，`errcode = -14` 时重新进入登录流程。
- 新增消息接收链路：`getupdates` 长轮询 + 游标（`get_updates_buf`）持久化 + 基于消息 id 的去重，保证重启不丢消息、不重复回复。
- 新增消息准入：白名单（`ALLOW_FROM`）+ 垃圾消息过滤（空消息、纯符号、超长、重复刷屏），不在白名单内的消息不进入 LLM 与多模态分支。
- 新增 OpenAI 兼容的回复生成：可配置 `base_url` / `api_key` / `model`，组装人设 prompt、长期摘要与最近若干轮对话；超时或失败时走兜底话术，不崩溃。
- 新增记忆：短期为固定容量 `deque`（默认 20 条），长期为按联系人聚合的 LLM 摘要，均以 JSON 落本地并在重启后恢复。
- 新增多模态占位：语音 / 图片 / 文件 / 视频首版不解码，统一走「暂不支持」降级回复，并预留处理器注册接口。
- 新增 `.env` 配置加载与启动校验、密钥脱敏日志、单实例文件锁、优雅停机。
- 新增测试（单元 + 集成）与 README、演示视频录制说明。
- **不涉及 BREAKING 变更**：这是一个全新项目，当前仓库没有既有实现。

## Capabilities

### New Capabilities

- `wechat-gateway`: 通过官方 iLink Bot 通道建立唯一、可恢复的消息收发链路——二维码登录、长轮询接收、游标持久化、去重、会话过期恢复、被动回复（`context_token`）约束、出站文本分片。
- `message-guard`: 在调用模型之前决定「这条消息值不值得回」——白名单准入、垃圾消息过滤、短路顺序与丢弃可观测。
- `ai-reply`: 把一条已准入的文本消息转换为一段符合人设、带近期上下文的回复，并在 LLM 超时 / 失败 / 空输出时保持可用。
- `conversation-memory`: 让回复具备跨轮、跨天连续性——按联系人隔离的短期窗口与长期摘要，持久化、重启恢复、损坏可恢复、可清空。
- `multimodal-fallback`: 首版不解析语音 / 图片 / 文件 / 视频，但这些消息必须得到确定性的降级响应，且为后续接入保留统一扩展点。
- `app-runtime`: 保证服务在 macOS 上可重复启动、配置错误早失败、运行状态可观测、敏感信息不进入代码与日志。

### Modified Capabilities

无。仓库当前没有任何既有 capability（`openspec list --specs` 为空），本次全部为新增。

## 不在范围内（Out of Scope）

- **群聊**：首版只处理单聊（iLink Bot 场景下也以单聊为主）。
- **主动触达**：不实现定时问候、批量推送、拉群。iLink 发送必须携带入站消息带来的 `context_token`，本质上只能被动回复。
- **完整多模态**：不做 ASR、OCR、文件解析，只做占位与降级。
- **Web 管理后台 / 可视化面板**：配置与运维护均通过 `.env` 与命令行完成。
- **多账号 / 多实例**：单进程、单微信号、单数据目录。
- **数据库**：首版用本地 JSON 文件持久化，不引入 SQLite / Redis。
- **消息内容审核与合规风控**：依赖白名单控制影响面，不做敏感词库。
- **打包为 macOS App / 开机自启守护**：以 `python -m` + 终端运行为交付形态。

## 风险与已知限制

- **被动回复限制**：iLink 要求回复携带当前入站消息的 `context_token`，无法主动发起会话；进程重启后旧 token 不可复用，只能等对方再次发消息。
- **登录需要人工介入**：首次与 `-14` 过期后都必须人工扫码，无法做到完全无人值守；`bot_token` 也不宜进仓库。
- **官方通道仍有策略风险**：iLink 属于腾讯侧的 Bot 能力，接口字段、限流与开关可能调整；社区曾报告 `sendmessage` 返回成功但消息未送达的情况，因此必须保留可观测性与降级路径。
- **个人号自动化风险**：任何个人号 Bot 都存在被风控限制的可能。建议使用小号、低频、仅白名单内回复，并在 README 中明确风险。
- **macOS 休眠**：合盖 / 休眠会中断长轮询与定时摘要；README 需给出防休眠建议（如 `caffeinate`），但不承诺后台常驻。
- **长期记忆依赖 LLM**：摘要失败时只能保留原始记录并延迟合并，不能保证摘要实时更新。
- **无群聊、无媒体解析**：首版能力边界明确，演示时需说明这是刻意的范围控制而非缺陷。

## Impact

- **新增代码**：`src/` 下的接入适配器、消息管线、过滤链、LLM 客户端、记忆存储、多模态占位、配置与日志；`tests/` 下的单元与集成测试。
- **新增依赖**：`httpx`（异步 HTTP）、`python-dotenv` 或 `pydantic-settings`（配置）、`pytest` + `pytest-asyncio` + `respx`/`pytest-httpx`（测试）；LLM 走 OpenAI 兼容 HTTP 接口，不强制绑定官方 SDK。
- **运行环境**：macOS（Apple Silicon / Intel 均可），Python 3.11+，无需 Node、无需 Windows、无需微信客户端。
- **配置与凭证**：人工提供的密钥（`LLM_API_KEY` 等）从 `.env` 读取；扫码获得的一次性 `bot_token` 属运行态凭证，落在 `data/` 下、权限 `0600`、被 `.gitignore` 覆盖，不写回 `.env`、不进日志。
- **对外副作用**：会以绑定微信号的身份向白名单联系人发送消息，属于用户可见行为；默认提供 `DRY_RUN` 开关便于联调。
- **对现有系统影响**：无（全新仓库，当前无提交与代码）。
